a document that is not a file

Welcome to Quartzite

You are reading a folder. This document is index.html, welcome.css and welcome.js, served together at their own URL so the relative paths just work. A markdown notebook could not hold this. That is the reason Quartzite exists.

Three shapes

A document is whichever of these fits the thing you are storing.

  • filea single notes.md or chart.html
  • folderan entry point plus its assets — like this one
  • zipthe same, served straight out of the archive

Two corpora, one graph

Point Quartzite at a vault — any folder of notes you already have — and it is indexed read-only: agents can link to it and search it, but never damage it. Everything written lands in the store instead.

Viewers are documents too

A file at viewers/<format>.html claims that format. It runs sandboxed and receives its target over postMessage. Adding support for a new format means writing a document — no Go code, no restart. 

curl -X POST localhost:5003/api/docs \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Rendering Notes",
    "format": "md",
    "content": "Cubed sphere beat icosphere.\n\nSee [[Welcome]]."
  }'
curl -X POST localhost:5003/api/docs \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Voxel Planet",
    "files": {
      "index.html": "<canvas id=c><script src=sim.js></script>",
      "sim.js":     "// runs at /d/{id}/sim.js"
    }
  }'
curl -X POST localhost:5003/api/docs \
  -H 'Content-Type: application/json' \
  -d '{
    "path": "viewers/csv.html",
    "content": "<script>
      addEventListener(\"message\", e => {
        if (e.data.type !== \"quartzite:doc\") return
        render(e.data.content)   // now .csv has a viewer
      })
      parent.postMessage({type:\"quartzite:ready\"}, \"*\")
    </script>"
  }'
